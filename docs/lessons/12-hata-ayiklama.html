Ders 12: Hata Ayıklama (Debugging)

📚 Orta Seviye ⏱️ 45 dakika 🎯 Hata Bulma ve Düzeltme

🎓 Debugging Sadece Hata Bulmak İçin Değil!

Çoğu kişi debugging'i (hata ayıklama) sadece "kod çalışmıyor, hatayı bulmalıyım" durumunda kullanır. Ama aslında debugging, kodu anlamak için de mükemmel bir araçtır!

📚 Öğrenme Aracı Olarak Debugging

Karmaşık bir kodu anlamakta zorlanıyorsan, console.log() veya breakpoint kullanarak kodu adım adım çalıştır. Her adımda değişkenlerin nasıl değiştiğini gözlemle. Özellikle şu konuları anlamak için çok faydalı:

  • İç içe döngüler: Hangi döngü kaç kez çalışıyor? i ve j değerleri nasıl değişiyor?
  • Çok boyutlu diziler: dizi[i][j] tam olarak neye erişiyor?
  • Fonksiyon çağrıları: Parametre değerleri neler? return ile ne dönüyor?
  • Recursion (özyineleme): Fonksiyon kendini çağırırken değerler nasıl değişiyor?
  • Nesne ve sınıflar: this hangi nesneyi gösteriyor?
💡 Pratik Öneri

Başkasının yazdığı karmaşık bir kodu anlamak istiyorsan:

  1. Kritik noktalara console.log() ekle
  2. Değişkenlerin değerlerini ve fonksiyonların ne zaman çağrıldığını izle
  3. Kağıt üzerinde veya zihninde değerleri takip et
  4. Kodu küçük parçalar halinde çalıştır ve gözlemle

Bu yöntem, sadece dokümantasyon okumaktan çok daha etkilidir! Görerek öğrenmek her zaman daha kalıcıdır.

🐛 Hata Türleri

Programlamada üç ana hata türü vardır:

1. Sözdizimi Hataları (Syntax Errors)

Yazım kurallarına uymayan kodlar. Program hiç çalışmaz.

// Yanlış: Parantez eksik
function setup() {
  createCanvas(400, 400   // ) eksik!
}

// Doğru:
function setup() {
  createCanvas(400, 400);
}

2. Çalışma Zamanı Hataları (Runtime Errors)

Kod çalışırken ortaya çıkan hatalar. Program çöker.

// Tanımsız değişken kullanımı
function draw() {
  circle(x, y, 50);  // x ve y tanımlı değil!
}

3. Mantık Hataları (Logic Errors)

Kod çalışır ama beklediğimiz gibi davranmaz. En zor bulunan hatalar!

// Topun sınırda dönmesi gerekiyor ama dönmüyor
if (x > width) {  // Yanlış: büyük yerine küçük olmalıydı
  hiz = -hiz;
}

📝 console.log() ile Hata Ayıklama

console.log() değişkenlerin değerlerini konsola yazdırır. Bu, kodun hangi aşamada ne değer aldığını görmek için çok kullanışlıdır.

💡 İpucu: Template Literal Kullanımı

Backtick (`) karakteri ile değişkenleri metin içine gömebilirsiniz:

let x = 100;
let y = 200;

// Eski yol:
console.log("X: " + x + ", Y: " + y);

// Yeni yol (daha temiz):
console.log(`X: ${x}, Y: ${y}`);

🔧 Tarayıcı Geliştirici Araçları (DevTools)

Tüm modern tarayıcılar güçlü geliştirici araçları içerir. Bu araçlar hata ayıklamanın en önemli yardımcısıdır.

DevTools'u Açmak İçin:

  • F12 tuşuna basın
  • veya Ctrl + Shift + I (Windows/Linux)
  • veya Cmd + Option + I (Mac)
  • veya Sayfaya sağ tıklayın → "İncele" (Inspect)

⏸️ Breakpoint ile Adım Adım İnceleme

Breakpoint (kesme noktası) kodu belirli bir satırda durdurup değişkenleri incelemenizi sağlar.

Breakpoint Nasıl Kullanılır?

  1. DevTools'u açın (F12)
  2. Sources sekmesine gidin
  3. Sol panelden dosyanızı bulun
  4. Durdurmak istediğiniz satır numarasına tıklayın (mavi nokta belirir)
  5. Sayfayı yenileyin - kod o satırda durur
  6. Sağ panelde değişken değerlerini görün

Kontrol Butonları

  • ▶️ Resume (F8): Sonraki breakpoint'e kadar devam et
  • ⏭️ Step Over (F10): Bir sonraki satıra geç
  • ⬇️ Step Into (F11): Fonksiyonun içine gir
  • ⬆️ Step Out (Shift+F11): Fonksiyondan çık

🛑 debugger Komutu

Kod içine debugger; yazarak programlı olarak breakpoint koyabilirsiniz.

⚠️ Önemli: debugger İçin Gerekli Adımlar
  1. DevTools'u açın: F12 veya sağ tık → "Incele" (Inspect)
  2. "Debugger" sekmesine gidin: Firefox'ta "Debugger", Chrome'da "Sources" sekmesi
  3. Kodu çalıştırın: debugger; satırına gelince kod otomatik durur

Not: DevTools kapalıyken debugger; hiçbir şey yapmaz. Ayrıca bazı tarayıcılarda "Console" sekmesinde değil, "Debugger/Sources" sekmesinde olmanız gerekir.

💡 İpucu

debugger; komutunu kullandıktan sonra silmeyi unutmayın! Aksi halde her ziyaretçide kod durur.

🎯 Hata Ayıklama Stratejileri

1. Son Çalışan Versiyona Dön

Kod çalışıyordu ve bir değişiklik yaptıktan sonra bozuldu mu? Son yaptığınız değişiklikleri geri alın (Ctrl+Z) veya yeni eklediğiniz kodları yorum satırına alın. Hata kaybolursa, sorun yeni eklenen kodda demektir.

2. Rubber Duck Debugging (Lastik Ördek)

Kodu birilerine (veya hayali bir ördeğe) satır satır açıklayın. Açıklarken genellikle hatayı kendiniz fark edersiniz!

3. Print Debugging

Şüphelendiğiniz her yere console.log() ekleyin. Değişkenlerin hangi noktada yanlış gittiğini bulun.

4. Minimal Örnek

Hatayı yeniden üretecek en küçük kodu yazın. Ne kadar az kod varsa, hata o kadar kolay bulunur.
